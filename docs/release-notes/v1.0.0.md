# Dev Agent Kit v1.0.0

Dev Agent Kit is a provider-neutral engineering agent kit for Claude Code and Codex: portable skills, a deterministic `dev-agent` CLI and an MCP server for visual validation. v1.0.0 is the first release published as an installable package (`dev-agent-kit`) and the first with a stated compatibility policy.

## Highlights since v0.5

- **Task orchestration (v0.7):** run a work item from any configured task source. A declarative `generic-mcp` mapping needs no code; a local ledger and a safe Git preparation (fast-forward only, never on a dirty tree) keep the work resumable.
- **Backend domain (v0.8, v0.10):** ten backend skills and twenty-five lazy references covering Python, Node.js, PHP, C#, Java and Ruby stacks, chosen from a deterministic project profile.
- **Fullstack contract (v0.9):** one persisted API contract per work item, verified against captured exchanges, an OpenAPI description and client source.
- **`dev-agent` CLI (v0.9):** `inspect`, `context audit`, `sources`, `task`, `contract`, plus `repo index`, `repo similar` and `diff review` (v0.11) to reuse existing patterns and review a diff before reporting done.
- **Shared engineering core (v0.6):** seven provider-neutral skills, repo memory stamped with the source commit, a context audit.

## Compatibility

Nothing was removed.

- `frontend-agent` and `frontend-agent-kit` remain installed as aliases of the same install/verify code, with the same commands and exit codes. There is no removal date; a future removal would ship with its own migration plan.
- The seven frontend skills keep their names, the five MCP tools keep their names, `.frontend-agent/config.yml` keeps working, and the 36 offline eval scenarios stay valid.
- See `docs/migration-from-frontend-agent.md`.

## Install

```bash
npm install -g dev-agent-kit-1.0.0.tgz     # the tarball attached to the GitHub release
dev-agent install --project /path/to/project
dev-agent verify --project /path/to/project
```

or from a checkout: `npm install && npm link` (see the README).

## Benchmarks

The real Claude and Codex benchmarks have **not been run** for this release. `npm run evals:validate` checks all 36 scenarios offline; `npm run bench` runs them against real hosts. Results will be added to `evals/results/` and to these notes by the project owner. Nothing in this release claims a benchmark result.

## Behavior notes

- `install` now stops with `could not find tsx` when the kit's `tsx` binary cannot be located (it looks in the kit's own `node_modules` and in each parent `node_modules`), instead of writing an MCP launcher path that does not exist. Skills and instruction files written before that point stay in place; rerun `install` after reinstalling the kit's dependencies.
- A relative `--project` is resolved against the caller's directory when npm runs the CLI from the kit checkout, and against the process directory everywhere else (an installed kit, a monorepo workspace script).

## Known limits

- Repository indexing, similar-feature search and diff review are heuristics over paths and names; they do not read source code, so they cannot see code-level idioms.
- A few backend reference documents have wording nits that were deferred.
- The package runs TypeScript through `tsx`; there is no precompiled build.
- No license file is included yet; add one before publishing to npm.
- Some CLI messages still say "kit checkout" or "frontend-agent verify" even for an installed copy or a `dev-agent` invocation; the alias output is kept unchanged on purpose.
