# Dev Agent Kit v1.1.0

v1.1.0 adds multi-repository workspaces: one root folder, several repositories, one work item.

## New

- **`workspaces:` in `.dev-agent/config.yml`** — a map of workspaces (path, role, `dependsOn`, optional `baseBranch`), with strict path safety (relative POSIX, inside the root, no symlinks, no nesting, at most 30).
- **`dev-agent workspaces`, `workspaces verify`, `workspaces order`** — per-workspace inspection, Git state, dependency order and version-pin checks (`ok`, `behind`, `ahead`, `unknown`, `not-declared`) read from `pyproject.toml` and `package.json`.
- **`--workspace <name>`** on `inspect`, `repo index`, `repo similar` and `diff review`; `diff review --workspace all` reviews every repository and skips the rest with a note.
- **Multi-repository task state, ledger and resume** — an optional per-workspace record, a `Workspaces` ledger section after `Git`, and `task status` reports every recorded workspace.
- **`producer` and `consumers` in the API contract** — `contract usage` scans each consumer without `--client`.
- **A `workspaces` reference** for the task-orchestrator skill (seven references now) and `docs/workspaces.md` with the Altave and Pumpkin layouts.

## Compatibility

A config without `workspaces` is unchanged: every command, the 26 skill names, the five MCP tool names, `.frontend-agent/config.yml`, existing task state JSON and existing ledgers keep working. New fields are optional. A v1.0 ledger gets the `Workspaces` section in place the first time it is written.

## Limits

- The CLI never creates branches, publishes or bumps versions; publishing a package version is always a stop-and-ask.
- Pin checks understand a small set of constraint forms and report anything else as `unknown`.
- No in-process contract between packages, no monorepo detection inside one repository, no benchmark scenario spanning several repositories.
- The real Claude and Codex benchmarks have **not been run** for this release; nothing here claims a benchmark result.
