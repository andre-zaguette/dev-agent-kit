# Dev Agent Kit v1.3.0

v1.3.0 adds native task sources: GitHub Issues, Linear, Jira and YouTrack can be read straight from the tracker's HTTP API, with no MCP server.

## New

- **Four native adapters** — `github-issues`, `linear`, `jira` and `youtrack`, configured in `.dev-agent/config.yml` with `tokenEnv` (the **name** of an environment variable; the value never reaches config, ledger, state or output), plus `baseUrl` (Jira, YouTrack, self-hosted GitHub), `emailEnv` and `auth` (Jira Cloud or bearer) and `repo` (GitHub).
- **`dev-agent task fetch <id> [--source s] [--json]`** — reads the item through the resolved native source and prints it, or the canonical `WorkItem` with `--json`. A handled failure exits 2 and starts with `unresolved:`, `not-found:`, `auth:` or `unavailable:`.
- **`sources verify`** checks native sources too: the config, and whether the token variable is set (never its value).
- **Orchestrator** — step 2 uses `task fetch` for native sources; an eighth reference, `native-sources`, covers the rules. `docs/native-task-sources.md` has one section per tracker and how to create a read-only token.

## Safety

HTTPS only; 15 s timeout; answers over 2 MB are refused; redirects are never followed, so the token cannot be sent to another host; errors are scrubbed of the token. At most 100 comments are read, and any list that is cut or fails is named in `metadata.partial`. Every adapter is read-only: it never comments on, transitions or links an item. `task fetch` is the only `dev-agent` command that opens a network connection.

## Compatibility

A config without native adapters is unchanged, and so are `generic-mcp` sources, the skill names and the MCP tool names. The four adapter names are now reserved: a config that used one of them for a custom adapter must rename it. The new config keys are valid only on the new adapters.

## Fixed

- `npm run validate:skills` rejected the `status: guide` of the five stack guides shipped in v1.2.0; it now accepts it, and a test guards it.
- `packages/evals` typecheck error (`includeFigma`) removed.

## Limits

- The Jira field names and the way Jira and Linear report a missing item could not be confirmed from the vendors' documentation; they are covered by a manual check with a real read-only token for each tracker, which has **not** been run for this release.
- The 2 MB cap is checked after the response is received, not while streaming. Attachments are metadata only; no search, no write, no OAuth.
- The real Claude and Codex benchmarks have **not been run** for this release; nothing here claims a benchmark result.
